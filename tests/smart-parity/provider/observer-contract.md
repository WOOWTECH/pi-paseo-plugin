# MCP observer contract and evidence history

The production standard uses the observer already on main at `fa2a024cdffd68b5d132167aa7d54129a67f7e11`. This PR does not change its implementation or the provider prompts. Compared with the earlier production source `f366f45ddafbc35276811cf82bcbd82ffed60881`, however, v10 **did change observer semantics** by incorporating the existing `de3e3efd82aac8939c7660514fb6c76aee9f5cba` and `d20f08db3b163b7f6e3a2e16de78ece66dbadbac` corrections. Describing that transition as an unchanged observer is inaccurate.

- Only the zero-parameter fixture `read_marker` opts into omitted dispatcher `args`, including the adapter's empty-string omission. The result must still be a completed successful call with the exact fixture marker.
- Supplied arguments may be an object or a JSON string encoding an object, including `{}`/`"{}"` for the zero-argument fixture. Malformed JSON, arrays, null and primitives are rejected.
- Generic dispatch must identify the expected server through a qualified tool name or an explicit matching top-level server. A conflicting explicit server is rejected even if the tool name is qualified. An unqualified tool without server binding is not proof of which server answered.
- Memory read/write still require the actual key/content/CAS fields and matching completed results; omission/empty arguments cannot satisfy them. Web writes also require the independent persisted revision and the original absent-read/write ordering. Missing tool events, greetings and assistant-only claims still fail.

Actual installed source was read locally at `/opt/woow/pi-agent-shared-runtime/node_modules/pi-mcp-adapter/index.ts`, package `pi-mcp-adapter@5.2.0`, SHA256 `0154c4ecdfcd6a8ff50d442debfc74e96f9d8d1dccd04f0817187f3e14b026cf`. Its `registerProxyTool` argument schema (lines2089–2095) makes `args` optional and accepts string or object. `parseArgs` (lines2132–2151) returns undefined for omission/empty string, parses strings, and rejects null/arrays/nonobjects. This is source-contract evidence, not a new provider turn or a claim about every installation.

The existing `acceptance-evidence.test.mjs` regressions exercise omitted and empty arguments, object/encoded-object arguments, conflicting/absent server binding, malformed arguments, completed/error results and mandatory memory parameters. The v10 full-capture pipeline also rejects a rehashed trace with missing MCP tool events. Tests and the adapter source observation do not rewrite prior evidence: every failed canonical attempt, original report/raw trace and original verdict remains unchanged. Later reruns have separate identities; no historical failed attempt is silently reclassified.
