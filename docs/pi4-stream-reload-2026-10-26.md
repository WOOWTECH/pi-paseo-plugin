## 根因與修正

本次官方網頁版本為 0.13.0，Pi4 插件維持 v0.1.8，管理的 daemon 為 0.11.2。後端對話沒有重複；問題發生在網頁恢復快取、補抓歷史與接收即時串流的交接處。

第一個問題是 `preserveReplacementHead` 僅以文字前綴判斷是否保留已被歷史涵蓋的 assistant 回覆。連續兩輪產生相同文字，再次準備快取時，較早的一輪可能重新進入即時顯示區，形成三個區塊。修補以 provider message ID 判斷是否同一回覆；沒有 provider ID 時，則使用列 ID 或同一 epoch／sequence。兩個已知不同的 provider ID 不會因文字相同而被合併，既有未帶 ID 的相容路徑仍保留。

第二個問題在長串流實測中發現：重連先收到回覆的中間片段，之後補抓到較早的 reasoning 與完整 assistant 時，片段可能先被寫進歷史，完成時的去重反而丟掉完整回覆。修補在重播歷史頁面前，移除已被同一 message ID、同一 epoch 且涵蓋其 sequence 的歷史單元取代的即時副本。較新的、尚未被涵蓋的內容仍保留。

## 已完成驗證

四個聚焦測試套件共 **202 項通過**，包含本次新增的七個回歸案例。原版本可以重現相同文字的重複列，以及長串流只剩中間片段；修補後通過。四個修改檔的格式、lint 及 `git diff --check` 均通過。

初次本機驗證使用精簡測試環境，將未使用的 app store 匯入替換為一旦被呼叫就會拋錯的 stub；本機全 app 型別檢查因缺少 Expo／workspace 相依而未完成。後續獨立 CI 已安裝完整 workspace 依賴、建置 app 相依套件，使用原 repo 測試設定且不加入該 stub，**202 項測試、app 完整型別檢查、修改檔的格式與 lint 全部通過**。CI 同時確認所有 `packages` 內容與修補 commit `043aa82` 相同；CI 分支僅增加驗證流程。這是本次修補的聚焦驗證，沒有宣稱整個上游 CI matrix 通過。

| 實測情境 | 結果 |
| --- | --- |
| 兩輪相同短回覆，重新整理後恢復 | 維持正確的兩則回覆，無 JavaScript 錯誤 |
| 長回覆仍在串流時重新整理 | 兩次複驗通過；重新整理前直接確認回合狀態為 `open` |
| 重連後長回覆完成 | 收到 `STREAM_DONE` 結尾，兩則回覆，輸入框可繼續使用 |
| 網頁與後端逐字比對 | 兩則回覆的文字及 message ID 完全一致；長回覆 4,723 字元 |
| 測試結束清理 | 僅歸檔本次專用且已 idle 的測試 agent；移除隔離瀏覽器 profile |

最後一次逐字比對時間為 **2026-10-26 06:30 UTC**。真實瀏覽器使用官方網頁、官方 relay 與 Pi4 的 Claude Code，在隔離 Playwright 瀏覽器中，以修補來源編譯的兩個模組替換下載的 JavaScript 模組。替換僅作用於該測試瀏覽器，沒有變更官方網站、Pi4 daemon、帳號設定或既有對話。

## 部署狀態與適用範圍

原始碼與回歸測試已在公開 fork，並送交上游 PR。官方網站的發布權限屬於上游；待上游合併、部署後，還需要用未注入修補的瀏覽器重新驗收，才能宣稱一般使用者已取得修正。現有 v0.1.8 安裝包不包含本次官方網頁修補，因此本次沒有重標 tag 或宣告新的插件版本。

本輪沒有重新驗收 Codex／Pi 串流重連、實體手機、語音或全部網路故障組合；先前三引擎完成回覆後的重新整理結果仍見[官方訂閱報告](pi4-official-subscription-2026-10-26.md)。上述結果證明已重現案例的修補，不代表整體商業上線條件已全部達成。
